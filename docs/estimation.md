# Оценка проекта 02-dagster: токены, лимиты, человекочасы, деньги

> Дата: 2026-09-20. Источник чисел — телеметрия сессий Claude Code в
> `~/.claude/projects/*mlinside*` (поля `usage` в транскриптах) и §3 `.claude/PLAN.md` (≈46 агент-часов).
> Цены API — из скилла `claude-api` (кэш на 2026-06-24). Всё, что помечено «оценка», — прогноз, а не факт.

## 1. Пять моделей оценки

| Модель | Как считает | Когда применима | Слабое место |
|---|---|---|---|
| **A. Измеренная телеметрия** | суммируем `usage` уже прошедших сессий | постфактум, и как база для аналогии | не предсказывает будущее |
| **B. Аналогия** | берём похожий завершённый проект и множим на коэффициент объёма | есть близкий аналог (здесь — `mlinside-dagster-demo`) | коэффициент субъективен |
| **C. Декомпозиция снизу вверх** | сумма оценок по задачам плана (S1…S6 + лейны) | есть подробный план | систематически занижает на 20–40 % |
| **D. Ставка токенов на агент-час** | агент-часы из плана × измеренный расход токенов в час | нужен быстрый пересчёт «часы → \$» | расход сильно зависит от параллельности |
| **E. Ценность для заказчика** | сколько стоит результат, а не затраты | фиксированная цена, продажа | не связана с себестоимостью |

Ниже — все пять на этом проекте. Для итога я беру B и C, а D использую как проверку.

## 2. Измерено (модель A)

| Блок | Период | Токены (out / cache write / cache read) |
|---|---|---|

Отсюда практический вывод: экономию дают короткие сессии и узкие подзадачи, а не «модель подешевле».

## 3. Токены на весь проект (модели A + B)

Реализация оценена как аналог × 1.6 (у нас больше объём: dlt, MLflow, Docker, Grafana, тесты, L-H).
Итог «всё вместе» = планирование (факт) + текущие сессии (факт) + реализация (прогноз) ≈ **730M токенов**,
из них ~700M — чтение кэша, 6M — генерация.

Стоимость по API-прайсу, если бы весь объём прошёл на одной модели:

| Этап | Fable 5.1 | Opus 5 | Sonnet 5 | Haiku 4.5 |
|---|---|---|---|---|
| Планирование (факт) | $249 | $149 | $60 | $30 |
| Текущие сессии (факт) | $43 | $29 | $12 | $6 |
| Реализация (прогноз) | $291 | $287 | $115 | $57 |
| **Весь проект** | **$765** | **$645** | **$258** | **$129** |

Цены: Fable 5.1 $10/$50 за 1M вход/выход, Opus 5 $5/$25, Sonnet 5 $2/$10, Haiku 4.5 $1/$5;
запись кэша 1.25× входа, чтение 0.1× (у Fable 5.1 — $0.25/1M).

Оговорки:
- Разница Fable 5.1 и Opus 5 мала именно потому, что у Fable дешёвое чтение кэша ($0.25 против $0.50).
- Haiku 4.5 в этой таблице — арифметика, а не прогноз: на задачах уровня «свести dbt-граф с Dagster»
  он потратит больше итераций, и реальная экономия окажется меньше четырёхкратной. Реалистичный сплит —
  Opus/Fable на план и отладку, Sonnet на рутину (тесты, YAML, докстринги): ≈ $350–450 за проект.
- Подписка Claude Code не тарифицируется по этим ценам. Таблица отвечает на вопрос «сколько бы стоило
  через API», то есть даёт верхнюю границу ценности подписки.

## 4. Пятичасовые окна подписки

Точного перевода «токены → процент лимита» нет: лимит считается на стороне сервиса и зависит от плана.
Оценка по наблюдаемому темпу работы (модель D):

| Этап | Плотных часов | Окон (оценка) |
|---|---|---|
| Планирование + разведка (факт) | ~6 при 6 параллельных лейнах | 2–3 |
| Реализация этапа 1 (S1…S6, последовательно) | ~14 | 3–4 |
| Лейны этапа 2 (A–H, по 3–4 параллельно) | ~10 wall-clock | 3–5 |
| **Итого** | | **8–12 окон**, то есть 3–5 рабочих дней в обычном ритме |

Параллельные субагенты — главный множитель: три лейна разом съедают окно примерно втрое быстрее.
На Fable 5.1 окна уходят быстрее, чем на Opus 5, при той же задаче. Точные цифры смотрите в `/usage`:
телеметрия сессий не содержит данных о лимитах, поэтому эта строка — единственная в документе,
которую я не могу подтвердить измерением.

Поправка на оптимизм декомпозиции (+25 %): **mid ≈ 135 ч, senior ≈ 90 ч.**

**Ваши часы при работе с агентами** — это не те же часы. Расход по факту двух дней: постановка и правка
`PROMPT.md`, ревью плана, ответы на вопросы агентов, ручная проверка демо, запись. Оценка: **18–28 ч**
вашего времени на весь проект, из них ~6 уже потрачено. Экономия относительно senior-варианта — примерно
3–4×, и она берётся из разведки и рутины, а не из архитектурных решений: их всё равно принимаете вы.

## 6. Деньги

**Себестоимость по часам** ($50/ч, средняя ставка mid/senior из условия):

| Сценарий | Часы | Стоимость |
|---|---|---|
| Mid без агентов | 135 | $6 750 |
| Senior без агентов | 90 | $4 500 |
| Вы + агенты | 23 | $1 150 + токены ($260–770 по API или 8–12 окон подписки) |

**Цена заказчику.** Три способа посчитать:

1. **Cost-plus:** senior-оценка × маржа 1.6 → **$7 000–7 500**.
2. **Фиксированная за результат** (демо-репозиторий + runbook + docs, без лекции): **$5 000–8 000**.
   Нижняя граница — если заказчик принимает демо «как есть», верхняя — с записью и правками под слайды.
3. **Как часть образовательного продукта** (лекция + демо + ДЗ + проверка): демо обычно составляет
   30–40 % бюджета модуля, то есть при цене модуля $18–25k доля демо — **$6 000–9 000**.

Для внутреннего проекта (демо к собственной лекции) осмысленная метрика — не цена, а альтернативная
стоимость: **90 часов senior-времени**, которые агенты превращают в ~23 ваших часа плюс $260–770 токенов.

## 7. Что делает оценку неверной

- Реализация ещё не начиналась: числа §3 для неё — прогноз по аналогии, а не измерение. Проверить
  можно после S4: если фактический расход отличается больше чем в полтора раза, пересчитать коэффициент 1.6.
- Отладка Docker и Grafana (L-E) — самый волатильный блок: исторически такие лейны выходят за оценку вдвое.
- Цены API кэшированы на 2026-06-24 и могут устареть.
- Перевод в окна подписки — экспертная оценка, см. §4.
