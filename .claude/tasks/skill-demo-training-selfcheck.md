# Спецификация скилла-кандидата `demo-training-selfcheck`

> По политике проекта файлы скиллов не пишутся напрямую — только через `/create-skill-candidate` /
> `/create-skill`. Эта спецификация — вход для них. Промоут: `/create-skill-candidate demo-training-selfcheck`
> (scope=prj), затем при необходимости `/create-skill`.

## Назначение

Самопроверка докладчика по материалу [`docs/theory/training-in-demo.md`](../../docs/theory/training-in-demo.md)
перед записью демо: скилл задаёт проверочные вопросы §10 по одному, сверяет ответ пользователя с эталоном из
блока `<details>`, ведёт счёт и в конце указывает разделы теории для повторения.

## Триггеры

`/demo-training-selfcheck`, фразы «проверь меня по обучению в демо», «самопроверка перед демо», «вопросы по
теории обучения».

## Алгоритм

1. Прочитать `docs/theory/training-in-demo.md`; извлечь список вопросов §10 и ответы из `<details>`.
2. Спросить режим: `все 10` (по умолчанию) / `случайные N` / `только сложные (7–10)`.
3. Для каждого вопроса: показать вопрос → дождаться ответа пользователя (свободный текст) → оценить по
   эталону: **верно** / **частично** (назвать, чего не хватает) / **неверно** (дать эталон и ссылку на раздел
   §1–§8 теории). Не подсказывать до ответа.
4. Итог: `верно/частично/неверно`, список разделов для повторения, рекомендация «готов к записи» при ≥8 верных.
5. Опционально: `--dry` — вывести все вопросы без опроса (для печати шпаргалки).

## Ограничения

Read-only: скилл ничего не пишет в репозиторий; работает офлайн; вопросы берутся из файла, не хардкодятся
(при изменении теории скилл менять не нужно).

## Файлы

- Источник: `docs/theory/training-in-demo.md` §10.
- Скилл: `~/.claude/skills/demo-training-selfcheck/SKILL.md` (создаётся через `/create-skill-candidate`).
