# reread-brd-and-sync-plan

Перечитать изменившиеся BRD-файлы (ТЗ) и аддитивно синхронизировать план с новыми
требованиями — без переписывания плана целиком и без правок кода.

## Когда использовать

- Хук `brd-watch` напечатал предупреждение `⚠️ BRD изменился: <path> (+a/-d строк)`
  (событие SessionStart или UserPromptSubmit).
- Пользователь просит: «перечитай ТЗ», «синхронизируй план с BRD», «учти изменения
  в PROMPT.md/SPEC.md».

## Вход

- Аргумент(ы): путь(и) к BRD-файлу(ам).
- По умолчанию (аргумент не передан) — файлы, отмеченные изменившимися в стампе
  хука `.ai/.brd-state.json` (репозиторий, см. `/add-session-hook` → `session_hooks.brd-watch`).
- Если стамп пуст/отсутствует — взять BRD-файлы репозитория по паттернам из
  `~/.ai/skills/_scripts/session/hooks/settings.yml#session_hooks.brd-watch.patterns`
  (та же SSoT, что у хука — список паттернов здесь не дублировать).

## Workflow

1. **Определить дельту.** Для каждого изменившегося BRD-файла сравнить текущую
   версию со снэпшотом `.ai/.brd-state/<slug>.prev` (либо `git diff <rev> -- <path>`,
   если снэпшота нет). Делегировать сравнение агенту `brd-watcher` (read-only):
   вход — пары (prev, current), выход — таблица «№ | тип (added/changed/removed) |
   цитата/строки | затронутый шаг плана | рекомендация».
2. **Показать дельту пользователю** — таблицей, со ссылками на строки (`path:LINE`).
3. **Обновить план аддитивно** — только там, где дельта его касается:
   - `PLAN.md` (или `docs/plan.md`, если `PLAN.md` отсутствует) — добавить/пометить
     пункты; никогда не удалять и не переписывать существующие пункты целиком —
     правки новыми строками с пометкой даты `(BRD-sync YYYY-MM-DD)`.
   - `docs/progress.md` — если файл существует, добавить запись о синхронизации.
   - `docs/decisions.md` — если дельта содержит решение (ADR-подобный пункт),
     добавить запись, не трогая прошлые.
4. **Залогировать событие** в `.claude/.PROMPTS-LOG.md` (и `-ru.md`) репозитория:
   дата, какие BRD-файлы, сколько пунктов дельты, какие файлы плана тронуты.
5. **Обновить стамп** `.ai/.brd-state.json` и снэпшоты `.ai/.brd-state/*.prev` на
   текущую версию (логика идентична хуку — если хук уже обновил стамп к моменту
   запуска скилла, этот шаг — no-op).
6. **Резюме** — короткий отчёт: какие BRD изменились, сколько пунктов дельты
   (added/changed/removed), какие файлы плана обновлены, что явно НЕ тронуто (код).

## Guardrails

- Не переписывать `PLAN.md`/`docs/*.md` целиком — только аддитивные правки с
  пометкой даты.
- Не трогать код и конфиги — только документы плана/прогресса/решений.
- Не задавать вопросов без необходимости — при неоднозначности делать разумное
  допущение и явно указывать его в резюме.
- Источник правды — файлы на диске (snapshot/diff), не память модели.

## Связанные объекты

- Хук: `session_hooks.brd-watch` (`~/.ai/skills/_scripts/session/hooks/`,
  тело — `scripts/session-hooks/brd-watch-hook.sh` в целевом репозитории) —
  обнаруживает изменения, обновляет стамп.
- Агент: `brd-watcher` (`~/.ai/subagents/brd-watcher.md`) — считает дельту между
  версиями BRD, read-only.

## Success Criteria

- [ ] Дельта требований показана (added/changed/removed, со ссылками на строки)
- [ ] `PLAN.md`/`docs/progress.md`/`docs/decisions.md` обновлены аддитивно там, где
      дельта их касается
- [ ] Код и конфиги не тронуты
- [ ] Событие залогировано в `.claude/.PROMPTS-LOG.md` (+ `-ru.md`)
- [ ] Стамп/снэпшоты обновлены
- [ ] Резюме выведено
